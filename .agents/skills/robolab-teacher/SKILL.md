# Classroom teacher
Evaluate whether a learner can start, recover, explain and resume a lesson with a realistic amount of adult help.

## Context
Read the selected project's AGENTS.md, BRIEF, CURRICULUM and relevant mission/QA documents. Inspect actual learner-facing code, instructions, layout and available review traces. Do not assume a class size, target FIRST SDK, device fleet or student experience that was not supplied. Use a beginner laptop session as a labeled starting assumption where needed. Pacing targets in planning documents are hypotheses.

## Review
- Trace entry → purpose → first meaningful edit → feedback → recovery → transfer → saved next step. Identify specific moments likely to require adult intervention and evidence already available.
- Compare Python and Java reading/syntax burden. Separate editable lesson choices from boilerplate while retaining required explanations.
- Check the returning-learner recap, terminology, visible goal and safe resume behavior. Treat shared-device and save behavior as technical claims requiring actual checks.
- Check whether recovery retains the experiment's context as well as its code: selected case, language, current-versus-starter prompts and a way back after loading an example. Separate guest and signed-in behavior; look for the first editable line and reachable help in each language.
- Assess whether learners can use free hints without waiting for the teacher. Preserve challenge for faster students through explanation and variations using taught concepts.
- Assess how concept, code, robot, console and help fit together at laptop/narrow widths. Inspect screenshots before making visual claims.
- Do not equate estimated reading time, automated task completion or a one-hour schedule with measured class pacing.

## Deliver
Prioritized intervention risks with exact source lines or screenshot names, smallest changes and a check that could confirm or disconfirm each risk, plus a practical session/observation plan. Label evidence as source-verified, screenshot/UI-observed, executed, historical report or learner hypothesis. Reading a test is not executing it. A source-only review can still provide a useful observation plan while naming unavailable checks. Observe first independent edit, prediction/reasoning, type of help, recovery, changed-case explanation and resume. Record actual elapsed time separately from infrastructure waiting. Use anonymized observations; do not include private student identifiers or credentials in repository artifacts.
State a target and criterion before a pilot, record per-observation outcomes without fabricating aggregate metrics, and distinguish completion from understanding. Review/plan only unless the user requests implementation. Invitations, messages and class scheduling require user authorization.
