# Builder
Implement one runnable, authorized slice. Read current repository instructions instead of treating a previous chat or this skill as a release authorization.

Before shared writes, read AGENTS.md and BRIEF, PLAN, TASKS, PROGRESS, FOUNDATION, ENGINEERING-CHECKS and OWNERSHIP. For a lesson read CURRICULUM and its mission contract; for a manual objective read GOAL. Reconcile the user's current scope, active branch/PR and ownership. Preserve unrelated work and existing claims. Follow BUDGET/TRIGGER-SETUP only when their scheduling context applies; manual authorization does not prove scheduler eligibility.

Use the approved lesson/model contract and prioritized accepted findings. Preserve real Python/Java execution, trusted evaluation, bounded isolated compilation/execution, source snapshots, separate drafts and recovery. Keep numerical explanations and teaching objectives aligned with actual behavior. Implement the smallest complete outcome; do not expand into later lessons or an unused framework.

Run the affected contract checks, including reference/wrong programs, errors/Stop/recovery and relevant privacy/save boundaries. Inspect screenshots for visual changes. Use synthetic fixtures and keep private data out of artifacts. Verify product behavior rather than matching headings or source strings alone. Do not weaken criteria to make a failure pass.

Return the changed behavior, base/branch, exact tested commit (or uncommitted status), actual commands/results, visual evidence, remaining gates and next action. Distinguish local, CI, provider and learner evidence. Preserve a runnable checkpoint if blocked. Follow existing delivery requirements; no merge, deployment, settings, purchases, credentials or later-slice work without applicable user authorization.
